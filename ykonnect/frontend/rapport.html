1. Contexte et objectifs

Le projet YKonnect est un hub d'articles IT et d'infrastructure destine aux etudiants en master systeme et reseau. Il s'inspire du site IT-Connect et propose :

  • Des procedures techniques detaillees (VPN, securite, load balancing)
  • Des cours de preparation a la certification CKA (Certified Kubernetes Administrator)
  • Un chatbot IA connecte, capable de rediriger vers les ressources internes du site

L'ensemble est deploye sur un serveur on-premise 192.168.4.80 via Docker et Ansible, et supervise par Prometheus et Grafana.

2. Infrastructure existante (avant YKonnect)

L'infrastructure on-premise etait deja deployee via Terraform avec les services suivants :

Serveur : 192.168.4.80 Orchestration : Docker (provider kreuzwerker/docker) Reseau Docker : app_network Services deployes : - nginx (port 80) : page d'accueil avec liens vers les outils - postgres (interne) : base de donnees PostgreSQL 15 - postgres_exporter (9187) : metriques PostgreSQL pour Prometheus - node_exporter (9100) : metriques systeme Linux - prometheus (9090) : collecte et stockage des metriques - grafana (3001) : dashboards de supervision - portainer (9000/9443) : gestion visuelle Docker

Page d'accueil d'infrastructure (port 80)

Une page HTML simple redirige vers les trois outils de supervision via des boutons. Un bouton YKonnect Website a ete ajoute pointant vers le port 8081.

3. Architecture YKonnect

Vue d'ensemble

192.168.4.80:8081 | v [nginx:alpine] <-- frontend container / --> fichiers statiques HTML/CSS/JS /api/ --> proxy_pass vers backend:8000 | v [FastAPI + Python 3.12] <-- backend container POST /api/chat --> appel API Groq GET /api/health --> healthcheck GET /metrics --> Prometheus scrape Reseaux Docker : ykonnect_net : frontend <-> backend (interne) app_network : backend <-> Prometheus (supervision)

Fichiers du projet

/opt/ykonnect/ (sur le serveur) frontend/ : site statique index.html : page d'accueil + chatbot articles.html : liste des articles wireguard.html : procedure WireGuard fail2ban.html : procedure Fail2Ban haproxy.html : procedure HAProxy certifications.html : parcours CKA cka-archi.html : module 1 - Architecture cka-workloads.html : module 2 - Workloads cka-networking.html : module 3 - Networking cka-securite.html : module 4 - Securite assets/css/styles.css : styles globaux assets/js/chat.js : logique chatbot assets/js/auth.js : hooks connexion/inscription backend/ main.py : FastAPI + Groq requirements.txt : dependances Python Dockerfile : image Python 3.12-slim nginx/nginx.conf : config reverse proxy docker-compose.yml : orchestration des containers .env : cle API Groq (confidentiel)

Docker Compose

services: backend: build: ./backend environment: [GROQ_API_KEY] networks: [ykonnect_net, app_network] frontend: image: nginx:alpine ports: ["8081:80"] volumes: - ./frontend:/usr/share/nginx/html:ro - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro networks: [ykonnect_net] networks: ykonnect_net: # reseau interne app_network: external # reseau partage avec Prometheus

4. Chatbot IA (Groq / Llama 3.3)

Choix technologique

Plusieurs options ont ete evaluees :

  • Ollama (local) : gratuit mais necessite min. 4 GB de RAM libre — impossible vu la RAM disponible (~1.2 GB libre)
  • Claude API (Anthropic) : payant (~$0.80/million tokens pour Haiku)
  • Groq API (retenu) : gratuit (1000 req/jour), modele Llama 3.3 70B, tres rapide

Backend FastAPI

Endpoint : POST /api/chat Modele : llama-3.3-70b-versatile Tokens : max 512 en sortie, temperature 0.6 Prompt : system prompt connait les pages du site et inclut des liens HTML dans les reponses

Comportement du chatbot

Le prompt systeme instruit le modele de :

  • Repondre en francais, de facon concise (5-8 lignes max)
  • Inclure des liens HTML cliquables vers les pages internes quand le sujet correspond
  • Rester dans le domaine IT/infrastructure

Metriques Prometheus

La librairie prometheus-fastapi-instrumentator expose automatiquement :

  • Nombre de requetes par code HTTP
  • Latence des requetes (histogramme p50/p95/p99)
  • Requetes en cours

5. Integration monitoring

Prometheus

Ajout d'un job de scrape dans prometheus.yml :

- job_name: 'ykonnect' static_configs: - targets: ['ykonnect-backend-1:8000'] metrics_path: /metrics

Le container backend est sur app_network (reseau partage avec Prometheus), ce qui permet la resolution DNS par nom de container.

Grafana

Dashboard "YKonnect - Chatbot" provisionne automatiquement avec 6 panels :

  • Requetes totales (stat)
  • Taux d'erreurs 5xx (stat, alerte rouge si > 0.1/s)
  • Latence p50 et p95 (stat)
  • Requetes/s par code HTTP (timeseries)
  • Latence p50/p95/p99 dans le temps (timeseries)

Portainer

Les containers ykonnect-frontend-1 et ykonnect-backend-1 sont visibles et gérables via l'interface Portainer sur le port 9000.

6. Deploiement Ansible

Inventaire

[ykonnect] 192.168.4.80 ansible_user=hau

Playbook deploy-ykonnect.yml

Le playbook effectue les operations suivantes dans l'ordre :

  1. Installation de python3-docker (SDK Ansible pour Docker)
  2. Verification que Docker est demarre
  3. Creation du repertoire /opt/ykonnect/
  4. Archive locale du projet (tar.gz), excluant le fichier .env
  5. Upload de l'archive et extraction sur le serveur
  6. Deploiement du fichier .env (cle Groq, mode 600)
  7. Copie du prometheus.yml mis a jour
  8. Build et demarrage des containers via docker compose up
  9. Rechargement de la configuration Prometheus (hot reload via HTTP POST)

Commande de deploiement

cd /home/hau/infra-deployment/ansible GROQ_API_KEY=<cle> ansible-playbook -i inventory.ini deploy-ykonnect.yml
Le hot reload Prometheus (/-/reload) necessite que le flag --web.enable-lifecycle soit actif dans la commande de demarrage du container, ce qui est le cas dans la config Terraform.

7. Contenu pedagogique

Procedures d'installation (3)

  • WireGuard VPN : generation de cles, config serveur/client Linux, pare-feu, roaming, debug
  • Fail2Ban : jails SSH et Nginx, filtres personnalises, gestion des bans, monitoring
  • HAProxy : load balancing HTTP, algorithmes, health checks, terminaison TLS, routage multi-site

Parcours CKA — 4 modules (sur 6)

  • Module 1 — Architecture : etcd, API Server, Scheduler, Controller Manager, kubelet, kube-proxy
  • Module 2 — Workloads : Pod, Deployment, DaemonSet, Job, CronJob, taints/tolerations, affinites
  • Module 3 — Networking : ClusterIP, NodePort, LoadBalancer, Ingress, NetworkPolicy, CoreDNS
  • Module 4 — Securite : RBAC, Role, ClusterRole, ServiceAccount, SecurityContext, Secrets

Modules prevus : Storage (PV/PVC/StorageClass) et Maintenance/Troubleshooting (kubeadm upgrade, etcd backup).

8. FAQ — Problemes rencontres et solutions

P1 — Port 8080 deja utilise

Symptome : Le site vitrine tourne deja sur le port 8080.

Solution : Changement du port expose dans docker-compose.yml de 8080 vers 8081.

ports: - "8081:80" # 8080 deja pris

P2 — Ansible et rsync non installes

Symptome : command not found: ansible

Solution :

sudo apt-get install -y ansible rsync sshpass

P3 — SSH : Host key verification failed

Symptome : Ansible ne peut pas se connecter au serveur.

Solution : Ajouter la cle publique du serveur dans known_hosts :

mkdir -p ~/.ssh && ssh-keyscan -H 192.168.4.80 >> ~/.ssh/known_hosts

P4 — Collection community.docker manquante

Symptome : couldn't resolve module/action 'community.docker.docker_compose_v2'

Solution :

ansible-galaxy collection install community.docker

P5 — Conflit docker.io / containerd.io

Symptome : containerd.io : Conflicts: containerd / runc lors de l'installation via apt.

Cause : Docker etait deja installe via le depot officiel Docker (non le paquet Debian docker.io).

Solution : Suppression de docker.io et docker-compose-plugin du playbook. On installe uniquement python3-docker (SDK Ansible).

P6 — Module synchronize echoue (sudo rsync sans TTY)

Symptome : sudo: un terminal est requis pour lire le mot de passe

Cause : Le module Ansible synchronize tente d'executer sudo rsync sur la machine distante, ce qui necessite un TTY interactif.

Solution : Remplacement par la combinaison archive (local) + copy (upload) + unarchive (extraction distante).

P7 — Prometheus ne scrape pas le backend YKonnect

Symptome : Le job ykonnect n'apparait pas dans les targets actives meme apres hot reload.

Cause : Le container Prometheus avait charge une ancienne version du fichier de config avant le redemarrage (probleme d'inode Docker avec le bind mount).

Solution : Redemarrage complet du container Prometheus :

docker restart prometheus

P8 — chat.js : SyntaxError Invalid or unexpected token

Symptome : Uncaught SyntaxError: Invalid or unexpected token (at chat.js:20:44)

Cause : Le fichier JS contenait des guillemets typographiques (curly quotes : " " U+201C/U+201D) au lieu de guillemets droits ASCII ("), introduits lors de l'edition. Le fichier avait aussi des fins de ligne Windows (\r\n) qui ont declenche l'erreur sur certains navigateurs.

Solution : Reecriture complete du fichier en ASCII pur, sans template literals ni caracteres Unicode, verifiee avec cat -A (absence de ^M).

# Verifier l'encodage d'un fichier JS file chat.js # doit indiquer "ASCII text" cat -A chat.js | head -5 # pas de ^M en fin de ligne

P9 — Chatbot confus avec le message "demo front"

Symptome : L'utilisateur pensait que le chatbot etait simule car le message d'accueil disait "demo front".

Solution : Mise a jour du message d'accueil dans index.html :

Bonjour ! Je suis le chatbot de YKonnect, propulse par Llama 3.3 (Groq). Pose-moi une question sur Linux, reseau, securite, Docker, Kubernetes...

P10 — Chatbot donnait de trop longues reponses textuelles

Symptome : Pour une question sur Kubernetes, le bot repondait avec de longues listes sans proposer les pages du site.

Solution : Mise a jour du prompt systeme pour :

  • Limiter les reponses a 5-8 lignes
  • Connaitre toutes les pages du site et inclure des <a href> HTML cliquables
  • Rediriger vers les ressources internes en priorite
