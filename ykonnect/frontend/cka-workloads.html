Module 2 — Workloads & Scheduling

Maîtriser les objets de charge de travail et le placement des Pods sur les nœuds.

CKA Workloads · ~2h · 15% examen

Pod — l'unité de base

Un Pod est le plus petit objet déployable dans Kubernetes. Il encapsule un ou plusieurs conteneurs qui partagent le même réseau et le même espace de stockage.

# Créer un Pod impératif (utile à l'examen) kubectl run nginx --image=nginx --port=80 # Générer le YAML sans créer (--dry-run=client -o yaml) kubectl run nginx --image=nginx --dry-run=client -o yaml > pod.yaml # Appliquer kubectl apply -f pod.yaml # Voir les Pods kubectl get pods -o wide # Détails et events kubectl describe pod nginx # Logs kubectl logs nginx -f # Shell interactif dans un conteneur kubectl exec -it nginx -- /bin/bash

Deployment

Gère un ensemble de Pods identiques avec rolling update et rollback.

apiVersion: apps/v1 kind: Deployment metadata: name: webapp namespace: default spec: replicas: 3 selector: matchLabels: app: webapp strategy: type: RollingUpdate rollingUpdate: maxSurge: 1 maxUnavailable: 0 template: metadata: labels: app: webapp spec: containers: - name: webapp image: nginx:1.25 ports: - containerPort: 80 resources: requests: cpu: "100m" memory: "128Mi" limits: cpu: "250m" memory: "256Mi"
# Scaler un Deployment kubectl scale deployment webapp --replicas=5 # Mettre à jour l'image kubectl set image deployment/webapp webapp=nginx:1.26 # Voir le statut du rollout kubectl rollout status deployment/webapp # Historique des déploiements kubectl rollout history deployment/webapp # Rollback vers la version précédente kubectl rollout undo deployment/webapp

DaemonSet

Assure qu'un Pod tourne sur chaque nœud du cluster (ou un sous-ensemble). Cas d'usage : collecte de logs (Fluentd), monitoring (node-exporter), agents réseau.

apiVersion: apps/v1 kind: DaemonSet metadata: name: node-exporter spec: selector: matchLabels: app: node-exporter template: metadata: labels: app: node-exporter spec: tolerations: - key: node-role.kubernetes.io/control-plane effect: NoSchedule containers: - name: node-exporter image: prom/node-exporter:latest

Jobs & CronJobs

# Job : tâche ponctuelle qui se termine apiVersion: batch/v1 kind: Job metadata: name: pi-calculator spec: completions: 3 # Nombre de succès requis parallelism: 2 # Pods parallèles template: spec: restartPolicy: Never containers: - name: pi image: perl command: ["perl", "-Mbignum=bpi", "-wle", "print bpi(2000)"]
# CronJob : tâche planifiée (syntaxe cron standard) apiVersion: batch/v1 kind: CronJob metadata: name: backup-db spec: schedule: "0 2 * * *" # Tous les jours à 2h jobTemplate: spec: template: spec: restartPolicy: OnFailure containers: - name: backup image: postgres:15 command: ["/bin/sh", "-c", "pg_dump ..."]

Limites de ressources

Toujours définir requests et limits pour permettre au scheduler de placer les Pods correctement et éviter la contention.

resources: requests: cpu: "200m" # 0.2 CPU garanti memory: "256Mi" # 256 MiB garanti limits: cpu: "500m" # Maximum 0.5 CPU memory: "512Mi" # OOMKill si dépassé

Taints & Tolerations

Les taints empêchent les Pods de s'exécuter sur un nœud, sauf s'ils ont la toleration correspondante.

# Ajouter un taint sur un nœud kubectl taint nodes node1 gpu=true:NoSchedule # Toleration dans le Pod pour accepter ce nœud tolerations: - key: "gpu" operator: "Equal" value: "true" effect: "NoSchedule"

Node Affinity & nodeSelector

# nodeSelector (simple) spec: nodeSelector: disktype: ssd # Node Affinity (plus puissant, avec operateurs) spec: affinity: nodeAffinity: requiredDuringSchedulingIgnoredDuringExecution: nodeSelectorTerms: - matchExpressions: - key: zone operator: In values: ["zone-a", "zone-b"]

Commandes clés pour l'examen

# Alias recommandés à l'examen alias k=kubectl export do='--dry-run=client -o yaml' export now='--force --grace-period 0' # Créer des ressources rapidement k create deployment web --image=nginx --replicas=3 $do > dep.yaml k create job myjob --image=busybox -- sleep 10 $do > job.yaml k create cronjob mycron --image=busybox --schedule="*/5 * * * *" -- date $do
💡 À l'examen, préférer kubectl create avec --dry-run=client -o yaml pour générer le YAML rapidement, puis l'ajuster si nécessaire.
