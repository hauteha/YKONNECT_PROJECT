Module 4 — Sécurité (RBAC & Pods)

RBAC, ServiceAccounts, SecurityContext, Secrets et sécurisation du cluster.

CKA Sécurité · ~2h · 12% examen

RBAC — Role-Based Access Control

RBAC contrôle qui peut faire quoi sur quelles ressources dans Kubernetes. Quatre objets principaux :

  • Role — permissions dans un namespace
  • ClusterRole — permissions cluster-wide (ou réutilisables)
  • RoleBinding — lie un Role à un user/group/SA dans un namespace
  • ClusterRoleBinding — lie un ClusterRole à l'échelle du cluster

Créer un Role

apiVersion: rbac.authorization.k8s.io/v1 kind: Role metadata: name: pod-reader namespace: default rules: - apiGroups: [""] # "" = core API group resources: ["pods", "pods/log"] verbs: ["get", "list", "watch"]

Lier le Role à un utilisateur

apiVersion: rbac.authorization.k8s.io/v1 kind: RoleBinding metadata: name: alice-pod-reader namespace: default subjects: - kind: User name: alice apiGroup: rbac.authorization.k8s.io roleRef: kind: Role name: pod-reader apiGroup: rbac.authorization.k8s.io

ClusterRole — lecture en lecture seule sur tout le cluster

apiVersion: rbac.authorization.k8s.io/v1 kind: ClusterRole metadata: name: global-reader rules: - apiGroups: ["*"] resources: ["*"] verbs: ["get", "list", "watch"]

Commandes RBAC impératives

# Créer un Role rapidement kubectl create role pod-reader --verb=get,list --resource=pods -n default # Créer un RoleBinding kubectl create rolebinding alice-pod-reader \ --role=pod-reader --user=alice -n default # Vérifier les permissions d'un utilisateur kubectl auth can-i list pods --as=alice kubectl auth can-i delete deployments --as=alice -n production # Lister les RoleBindings kubectl get rolebinding,clusterrolebinding -A | grep alice

ServiceAccounts

Les ServiceAccounts permettent aux Pods de s'authentifier auprès de l'API Server. Chaque Pod utilise un SA (par défaut : default).

# Créer un ServiceAccount kubectl create serviceaccount monitoring -n default # Associer un Role au ServiceAccount kubectl create rolebinding monitoring-binding \ --role=pod-reader \ --serviceaccount=default:monitoring # Utiliser le SA dans un Pod spec: serviceAccountName: monitoring automountServiceAccountToken: false # Désactiver si non nécessaire

Secrets

Les Secrets stockent des données sensibles encodées en base64. Pas chiffrés par défaut — activer EncryptionConfiguration en production.

# Créer un Secret générique kubectl create secret generic db-creds \ --from-literal=username=admin \ --from-literal=password=S3cr3t! # Secret pour une image Docker privée kubectl create secret docker-registry regcred \ --docker-server=registry.monentreprise.fr \ --docker-username=user \ --docker-password=pass
# Injecter un Secret en variable d'environnement env: - name: DB_PASSWORD valueFrom: secretKeyRef: name: db-creds key: password # Monter un Secret en volume volumes: - name: secret-vol secret: secretName: db-creds volumeMounts: - name: secret-vol mountPath: /etc/secrets readOnly: true

SecurityContext

Définit les paramètres de sécurité d'un Pod ou d'un conteneur.

spec: securityContext: runAsUser: 1000 # UID de l'utilisateur runAsGroup: 3000 # GID principal fsGroup: 2000 # GID pour les volumes runAsNonRoot: true # Refuser root containers: - name: app image: nginx securityContext: allowPrivilegeEscalation: false readOnlyRootFilesystem: true # FS en lecture seule capabilities: drop: ["ALL"] # Retirer toutes les capabilities Linux add: ["NET_BIND_SERVICE"] # Réajouter uniquement ce qui est nécessaire

Certificates & TLS dans le cluster

# Voir les certificats du cluster sudo ls /etc/kubernetes/pki/ # ca.crt, apiserver.crt, etcd/ca.crt... # Décoder un certificat openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -text | grep -A2 "Subject\|Issuer\|Not After" # Approuver une CSR (Certificate Signing Request) kubectl get csr kubectl certificate approve <nom-csr> kubectl certificate deny <nom-csr>

kubeconfig & Contextes

# Voir la config actuelle kubectl config view # Lister les contextes kubectl config get-contexts # Changer de contexte kubectl config use-context prod-cluster # Créer un contexte pour un namespace kubectl config set-context --current --namespace=production
💡 Mémoriser : kubectl auth can-i pour vérifier les permissions, --as= pour tester en tant qu'autre user.
⚠️ Ne jamais monter le token SA si le Pod n'appelle pas l'API Kubernetes. Utiliser automountServiceAccountToken: false.
