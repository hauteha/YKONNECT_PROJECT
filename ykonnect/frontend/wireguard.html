Mise en place d'un VPN WireGuard

Déployer un VPN moderne, rapide et sécurisé entre un serveur Linux et des clients.

Catégorie : Réseau Sécurité · Niveau : Intermédiaire · 25 min · Mise à jour : 2026-05-01

Pourquoi WireGuard ?

WireGuard est un protocole VPN moderne intégré au noyau Linux depuis la version 5.6. Comparé à OpenVPN ou IPsec, il offre :

  • Performances élevées — chiffrement ChaCha20-Poly1305 optimisé
  • Surface d'attaque réduite — ~4 000 lignes de code contre ~400 000 pour OpenVPN
  • Configuration simple — paires de clés publique/privée, pas de CA
  • Roaming transparent — le client change d'IP sans couper le tunnel

Architecture cible

Un serveur (peer A) expose le VPN, un ou plusieurs clients (peer B, C…) s'y connectent. Tous les peers sont équivalents dans WireGuard — c'est une logique point-à-point.

Internet │ ▼ [Serveur WireGuard] 192.168.4.80 wg0 : 10.8.0.1/24 ├── Peer Client1 → 10.8.0.2/32 └── Peer Client2 → 10.8.0.3/32

1. Installation

Sur Debian/Ubuntu (serveur et clients) :

sudo apt update && sudo apt install -y wireguard

Sur Fedora/RHEL :

sudo dnf install wireguard-tools

2. Génération des clés

Pour chaque peer (serveur + chaque client), générer une paire de clés :

# Générer la clé privée wg genkey | tee /etc/wireguard/privatekey | wg pubkey > /etc/wireguard/publickey # Restreindre les permissions chmod 600 /etc/wireguard/privatekey # Afficher les clés cat /etc/wireguard/privatekey cat /etc/wireguard/publickey
💡 La clé privée ne quitte jamais la machine. Seule la clé publique est partagée.

3. Configuration du serveur

Créer /etc/wireguard/wg0.conf :

[Interface] Address = 10.8.0.1/24 ListenPort = 51820 PrivateKey = <CLEE_PRIVEE_SERVEUR> # Activation du routage IP PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE # ── Peer : Client1 ────────────────────────────── [Peer] PublicKey = <CLEE_PUBLIQUE_CLIENT1> AllowedIPs = 10.8.0.2/32

4. Activation du routage IP

# Activer le forwarding (persistant) echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.conf sudo sysctl -p

5. Démarrage et activation du service

# Démarrer l'interface sudo wg-quick up wg0 # Activer au démarrage sudo systemctl enable wg-quick@wg0 # Vérifier l'état sudo wg show

6. Ouverture du pare-feu

# UFW sudo ufw allow 51820/udp sudo ufw reload # iptables direct sudo iptables -A INPUT -p udp --dport 51820 -j ACCEPT

7. Configuration d'un client Linux

Sur la machine client, créer /etc/wireguard/wg0.conf :

[Interface] Address = 10.8.0.2/24 PrivateKey = <CLEE_PRIVEE_CLIENT> DNS = 1.1.1.1 [Peer] PublicKey = <CLEE_PUBLIQUE_SERVEUR> Endpoint = 192.168.4.80:51820 AllowedIPs = 0.0.0.0/0 # Tout le trafic passe par le VPN PersistentKeepalive = 25
sudo wg-quick up wg0
💡 AllowedIPs = 0.0.0.0/0 → full tunnel (tout le trafic passe par le VPN).
AllowedIPs = 10.8.0.0/24 → split tunnel (seulement le réseau VPN).

8. Configuration d'un client Windows / macOS

Télécharger le client WireGuard officiel, puis importer le fichier wg0.conf généré ci-dessus via l'interface graphique. Le format est identique.

9. Vérification

# Sur le serveur — voir les peers connectés et le trafic sudo wg show # Ping depuis le client vers le serveur (adresse VPN) ping 10.8.0.1 # Vérifier l'IP publique vue depuis le client curl ifconfig.me

10. Ajouter un deuxième client

Générer les clés sur le client2, puis ajouter un bloc [Peer] dans le conf serveur :

[Peer] PublicKey = <CLEE_PUBLIQUE_CLIENT2> AllowedIPs = 10.8.0.3/32
# Recharger à chaud sans couper les sessions existantes sudo wg addconf wg0 /etc/wireguard/wg0.conf

Dépannage

  • Vérifier les règles iptables : sudo iptables -L -n -v
  • Logs du service : sudo journalctl -u wg-quick@wg0 -f
  • Tester le port UDP : nc -zvu 192.168.4.80 51820
  • S'assurer que ip_forward est bien à 1 : cat /proc/sys/net/ipv4/ip_forward
⚠️ Ne jamais exposer le fichier privatekey — traiter comme un secret (vault, variable d'env).
