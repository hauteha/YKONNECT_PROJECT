Mise en place d'HAProxy comme load balancer

Déployer un reverse proxy haute disponibilité avec répartition de charge et health checks.

Catégorie : Réseau Cloud · Niveau : Intermédiaire · 30 min · Mise à jour : 2026-05-01

Présentation d'HAProxy

HAProxy (High Availability Proxy) est un load balancer et reverse proxy TCP/HTTP de référence dans l'industrie. Il est utilisé par des entreprises comme GitHub, Twitter et Airbnb pour distribuer des milliards de requêtes. Ses points forts :

  • Répartition de charge — round-robin, least-conn, source IP hash…
  • Health checks — détection automatique des backends défaillants
  • Terminaison SSL/TLS — gestion des certificats en frontal
  • Page de stats — tableau de bord intégré en temps réel
  • ACL puissantes — routage conditionnel basé sur host, path, headers

Architecture cible

Internet │ ▼ [HAProxy :80/:443] ← reverse proxy / load balancer ├── backend1 : 192.168.4.10:8080 ├── backend2 : 192.168.4.11:8080 └── backend3 : 192.168.4.12:8080

1. Installation

sudo apt update && sudo apt install -y haproxy sudo systemctl enable haproxy

Vérifier la version :

haproxy -v

2. Structure du fichier de configuration

HAProxy utilise un seul fichier /etc/haproxy/haproxy.cfg avec 4 sections principales :

  • global — paramètres process (user, logs, limits)
  • defaults — valeurs par défaut pour les frontends/backends
  • frontend — écoute les connexions entrantes
  • backend — pool de serveurs qui traitent les requêtes

3. Configuration complète (HTTP load balancer)

global log /dev/log local0 log /dev/log local1 notice chroot /var/lib/haproxy stats socket /run/haproxy/admin.sock mode 660 level admin stats timeout 30s user haproxy group haproxy daemon maxconn 50000 defaults log global mode http option httplog option dontlognull option forwardfor # Transmet l'IP réelle du client en X-Forwarded-For option http-server-close timeout connect 5s timeout client 30s timeout server 30s errorfile 400 /etc/haproxy/errors/400.http errorfile 503 /etc/haproxy/errors/503.http # ── Frontend : écoute les requêtes entrantes ───────────────── frontend http_front bind *:80 default_backend webservers # Redirection HTTP → HTTPS (si TLS activé) # redirect scheme https if !{ ssl_fc } # ── Backend : pool de serveurs ──────────────────────────────── backend webservers balance roundrobin # Algorithme : round-robin option httpchk GET /health # Health check sur /health http-check expect status 200 server web1 192.168.4.10:8080 check inter 5s rise 2 fall 3 server web2 192.168.4.11:8080 check inter 5s rise 2 fall 3 server web3 192.168.4.12:8080 check inter 5s rise 2 fall 3 backup # ── Page de statistiques ────────────────────────────────────── frontend stats bind *:8404 stats enable stats uri /stats stats realm HAProxy\ Statistics stats auth admin:motdepasse_fort stats refresh 10s stats show-legends stats show-node

4. Algorithmes de répartition

  • roundrobin — distribution cyclique (défaut, stateless)
  • leastconn — vers le serveur ayant le moins de connexions actives
  • source — hash de l'IP source → même client, même serveur (sessions persistantes)
  • uri — hash de l'URI (utile pour les caches)
  • first — remplit le premier serveur avant d'utiliser le suivant

5. Terminaison TLS (HTTPS)

Concaténer le certificat et la clé dans un seul fichier .pem :

cat /etc/letsencrypt/live/monsite.fr/fullchain.pem \ /etc/letsencrypt/live/monsite.fr/privkey.pem \ > /etc/haproxy/certs/monsite.pem chmod 600 /etc/haproxy/certs/monsite.pem
frontend https_front bind *:443 ssl crt /etc/haproxy/certs/monsite.pem http-request set-header X-Forwarded-Proto https default_backend webservers

6. Routage par nom de domaine (multi-site)

frontend http_front bind *:80 use_backend app1_backend if { hdr(host) -i app1.mondomaine.fr } use_backend app2_backend if { hdr(host) -i app2.mondomaine.fr } default_backend app1_backend backend app1_backend server app1 192.168.4.10:8080 check backend app2_backend server app2 192.168.4.11:8080 check

7. Vérification et rechargement

# Valider la syntaxe avant de recharger sudo haproxy -c -f /etc/haproxy/haproxy.cfg # Recharger sans couper les connexions existantes (graceful) sudo systemctl reload haproxy # Vérifier le statut sudo systemctl status haproxy # Voir les logs sudo tail -f /var/log/haproxy.log

8. Page de statistiques

Accéder à http://<IP>:8404/stats pour voir en temps réel :

  • État de chaque backend (UP/DOWN)
  • Sessions actives, requêtes/s, taux d'erreurs
  • Poids et état des health checks
💡 HAProxy peut être combiné avec Keepalived pour une haute disponibilité active/passive avec IP virtuelle (VIP).
💡 En production, utiliser Certbot + Let's Encrypt pour les certificats TLS avec renouvellement automatique.
