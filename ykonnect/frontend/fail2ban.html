Protéger ses services avec Fail2Ban

Bloquer automatiquement les IP qui effectuent des tentatives d'intrusion répétées.

Catégorie : Sécurité Système · Niveau : Débutant · 20 min · Mise à jour : 2026-05-01

Principe de fonctionnement

Fail2Ban analyse en temps réel les fichiers de logs des services (SSH, Nginx, Apache, Postfix…). Lorsqu'une IP dépasse un seuil de tentatives échouées, elle est automatiquement bannie via iptables/nftables pour une durée configurable.

  • Filter — expression régulière qui détecte les échecs dans les logs
  • Jail — association d'un filtre + d'une action + des seuils
  • Action — ce qui est fait lors d'un ban (iptables, firewalld, email…)

1. Installation

sudo apt update && sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban sudo systemctl status fail2ban

2. Fichier de configuration

Ne jamais modifier /etc/fail2ban/jail.conf directement — il est écrasé lors des mises à jour. Créer à la place :

sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local

Ou créer un fichier dédié (approche recommandée) :

sudo nano /etc/fail2ban/jail.d/custom.conf

3. Configuration de la jail SSH

Contenu de /etc/fail2ban/jail.d/custom.conf :

[DEFAULT] # Ignorer ses propres IP (admin, monitoring...) ignoreip = 127.0.0.1/8 ::1 192.168.4.0/24 # Durée du ban : 1 heure bantime = 3600 # Fenêtre d'observation : 10 minutes findtime = 600 # Nombre de tentatives avant ban maxretry = 5 # Envoyer un mail lors d'un ban (optionnel) # destemail = admin@example.com # sendername = Fail2Ban # action = %(action_mwl)s [sshd] enabled = true port = ssh logpath = %(sshd_log)s backend = %(sshd_backend)s maxretry = 3

4. Protéger Nginx (authentification)

[nginx-http-auth] enabled = true port = http,https logpath = /var/log/nginx/error.log maxretry = 5 [nginx-botsearch] enabled = true port = http,https logpath = /var/log/nginx/access.log maxretry = 2

5. Redémarrer et vérifier

# Recharger la configuration sudo fail2ban-client reload # Voir le statut de toutes les jails sudo fail2ban-client status # Voir les IP bannies pour SSH sudo fail2ban-client status sshd

6. Gestion des bans manuels

# Débannir une IP manuellement sudo fail2ban-client set sshd unbanip 203.0.113.42 # Bannir manuellement une IP sudo fail2ban-client set sshd banip 203.0.113.42 # Voir les règles iptables générées sudo iptables -L f2b-sshd -n --line-numbers

7. Tester un filtre personnalisé

Avant d'activer une jail, tester le filtre sur les logs existants :

# Tester le filtre SSH sur les logs sudo fail2ban-regex /var/log/auth.log /etc/fail2ban/filter.d/sshd.conf # Résultat attendu : nombre de matchs trouvés # Lines: 1247 lines, 0 ignored, 42 matched, 1205 missed

8. Créer un filtre personnalisé

Exemple pour bloquer les scans de ports via Nginx :

sudo nano /etc/fail2ban/filter.d/nginx-scan.conf
[Definition] failregex = ^<HOST> -.*"(GET|POST|HEAD) /(admin|wp-login|phpmyadmin|\.env).*" (404|403) ignoreregex =
[nginx-scan] enabled = true port = http,https filter = nginx-scan logpath = /var/log/nginx/access.log maxretry = 3 bantime = 86400

Logs et monitoring

# Logs Fail2Ban en temps réel sudo tail -f /var/log/fail2ban.log # Statistiques globales sudo fail2ban-client status # Intégrer avec journald sudo journalctl -u fail2ban -f
💡 Penser à ajouter son IP d'administration dans ignoreip pour ne pas se baner soi-même lors de tests.
⚠️ Fail2Ban ne remplace pas un pare-feu. C'est une couche supplémentaire — toujours combiner avec UFW ou iptables.
